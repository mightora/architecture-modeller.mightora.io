# Business process mapping

Create a Process with a name, description and owner. Nest child processes/steps using Child. Documentation supports capability, criticality, inputs, outputs, dependencies, risks and assumptions. Activity type records activity, decision, start or end. These are lightweight architecture process maps, not executable BPMN.

Use Business mappings → Process followed by process for a sequence. A step's activity type is structured metadata; the current canvas retains the established block notation rather than claiming formal BPMN symbols.

Map Component supports process to the exact parent process or step. One system can support several processes, and a process can use several systems. Assign stakeholders with participation/RACI. The process view shows supporting systems as external context when enabled.

For swimlanes, record each activity's Swimlane and enable View settings → Use process swimlanes. Save the view. The swimlane layout flattens visible activities for readability without changing their master containment hierarchy.

Validation identifies important processes without an explicit support link. A parent's support mapping is not silently inherited by child steps. Use exact mappings to document what implements the activity. Word/PPTX design packs include the supporting systems, stakeholders and process documentation.

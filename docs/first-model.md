# Create your first model

The on-screen **Create your first model** wizard names a solution and chooses a blank model or one of nine templates. You can skip it and continue an existing model. The guide is also available from **Build your first model**.

1. Choose the question your model should answer and its audience. Capture this in the model description.
2. Name the solution. A useful example is Customer request service.
3. Select a template. Simple web application provides shared technical, process and stakeholder views.
4. Add systems and applications. Name actual responsibilities, then document an owner and criticality.
5. Add relationships. Describe exact endpoints and whether integration is synchronous, asynchronous or event-based in its documentation.
6. Save an overview view. Open a system and add its internal applications/services. Save a detailed view.
7. Add a business process. Add child activities and decisions; use sequence links and optional swimlanes.
8. Add stakeholders. Use Business mappings to assign participants/RACI and supporting systems to the process or step.
9. Add documentation, source links and an ADR for an important decision. Set component viewpoint tags where specialist projections need different content.
10. Validate. Locate each relevant finding, fix its source documentation, and validate again. Rules are a checklist rather than proof of good architecture.
11. Save a `.archmodel.json` file. Import it again or open it in VS Code to confirm portability.
12. Export the current view to Word and PowerPoint. Use Export options → Entire model for a full design pack.

The existing in-editor contextual guide groups these activities into eight concise stages; the start wizard lists all twelve actions. Example ownership and security information is illustrative and should be reviewed before use.
